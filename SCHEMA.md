# KIT DSN Dossier Schema — Observed vs. Documented

Analysis of all 4,167 mirrored snapshots (2015-07-15 → 2026-07-27, 25.42 GB raw).
Generated by [scripts/schema_scan.sh](scripts/schema_scan.sh), which enumerates every
leaf path and JSON type per file (node-id level stripped).

The official documentation is mirrored at [docs/kit-dsn-data.html](docs/kit-dsn-data.html)
(originally the bottom of <https://www.dsn.kastel.kit.edu/bitcoin/data.html>).

## File structure

Each `YYYYMMDD_HHMMSS_dossier.json` is a single JSON object mapping a 16-hex-char
node id (anonymized peer identifier) to a node record. The snapshot timestamp exists
only in the filename — any conversion must carry it into the data.

## Schema timeline

- **2015-07-15** — baseline: `lastConnect`, `ip.version`, `geo`, `whois`, `latency` only.
- **2016-01-29** — `versionstr` appears; `services` and `versionid` appear but as literal `null`.
- **2016-06-16** — `ip.tunnel`, `ip.tunnelclient`, `ip.tunnelserver` appear.
- **2017-05-20** — `services` and `versionid` start carrying numbers (per-node `null`s still occur through 2026-01).
- **2018-01-23** — `inv.invperhour` and `inv.meandelay` appear.
- **2018-05-24** — `inv.txperhour`, `inv.blockperhour`, `inv.meandelayblock` complete the `inv` block.
- **2023-03-28** — `ip.tunnelserver` (teredo server hash) last observed.

## Deviations from the documentation

1. **`geo.long` vs `geo.lon`** — the docs name the longitude field `lon`; the data has
   always used `long`.
2. **`inv` block is documented unconditionally** but only exists from 2018-01-23 on.
3. **`services`/`versionid`/`versionstr` absent before 2016-01-29**, and
   `services`/`versionid` were literal `null` for every node until 2017-05-20.
4. **`versionstr` appears as the number `0`** (instead of a string) for isolated nodes
   in 15 files between 2021-08-04 and 2021-10-06.
5. **`whois` sub-fields can be `null`**; the docs don't mention nullability.

## Known-bad source files

These defects exist on the KIT server itself (downloads verified by size and sha256):

- **Empty snapshots** (`{}`, 2 bytes): `20160221_125956`, `20160430_121909`,
  `20160502_121957`, `20160503_122021`, `20210708_124700`, `20211012_123000`.
- **Truncated snapshot**: `20190522_121247_dossier.json` is exactly 2 MiB
  (2,097,152 bytes) and is not valid JSON — cut off mid-string at the source.
  Any JSON→Parquet pipeline must special-case or skip it.

Additionally, ~230 calendar days in the range have no snapshot at all, and some days
have several (one day, 2024-11-28, has 13).
